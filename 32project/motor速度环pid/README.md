# STM32 CAN 控制 DJI M3508：速度 PID 与反馈滤波

第一次把 CAN 通信和 PID 用到实际电机控制中的学习工程。使用 STM32F103C8、TJA1050 CAN 模块和 DJI M3508 电机，通过电调读取转速反馈、发送电流指令，并用匿名上位机调节参数和观察曲线。

当时电机空载运行，转速波动，难以收敛到目标值；加入速度反馈低通滤波后，收敛情况有了改善。这次调试让我把滤波与闭环控制联系起来，开始关注反馈处理对控制效果的影响。

## 硬件与环境

| 项目 | 配置 | 接口或说明 |
| --- | --- | --- |
| 主控 | STM32F103C8，标准外设库 V3.5.0 | 工程目标为 STM32F103C8，Flash 64 KB、RAM 20 KB |
| 电机与通信 | DJI M3508、CAN 电调、TJA1050 模块 | 电调具体型号以实际硬件为准 |
| CAN1 | 正常模式，1 Mbit/s | PA12 → TJA1050 TXD，PA11 ← RXD；CANH、CANL 接电调 |
| 上位机串口 | USART1，115200、8N1，匿名 V7 协议 | PA9 TX → USB 转串口 RX；PA10 RX ← TX；共地 |
| OLED | 软件模拟 I²C | PB6 SCL、PB7 SDA |
| 时钟与编译器 | HSE 默认 8 MHz，系统 72 MHz；ARMCC 5.06 update 7 | CAN 外设时钟 36 MHz；Keil 工程入口为 `project.uvprojx` |

电机电源通过电调接入，接线前断电并固定电机。TJA1050 模块供电、RXD 电平及 MCU 引脚兼容性按实际模块原理图确认；CAN 总线两端配置终端电阻，调试时准备硬件断电方式。

## 控制流程与代码入口

**电调反馈 → CAN 接收解析 → 转速低通滤波 → 速度 PID → CAN 电流指令 → 电调。** 主循环实际控制第 1 个电机，另外三个通道保留反馈结构，发送的控制指令为 0。

| 文件 | 作用 | 关键配置 |
| --- | --- | --- |
| `main.c` | 初始化、反馈滤波、速度环与上位机调参 | 目标转子转速 1000 RPM；滤波系数 `0.2f` |
| `Hardware/MyCan.c` | CAN1 初始化、接收中断与发送 | 分频 4，BS1=6 tq，BS2=2 tq；36 MHz ÷ [4 × (1+6+2)] = 1 Mbit/s |
| `Hardware/MOTOR.c` | 电机反馈解析与控制报文封装 | 发送 `0x200`；接收 `0x201`～`0x204`；电机报文高字节在前 |
| `Hardware/Pid.c` | 位置式 PID、积分与输出限幅、停机状态清零 | 初始化 Kp=4、Ki=0.1、Kd=0.1；两项限幅均为 ±2000 |
| `Hardware/AND_DT.c`、`Usart.c` | 匿名协议与串口通信 | 上报四组滤波转速和目标值，接收调参数据 |
| `Libraries/`、`Start/`、`User/`、`System/` | 标准库、启动、中断模板和延时 | Keil 使用 `startup_stm32f10x_md.s` |

速度滤波使用上一轮结果和当前读数加权：`y[k] = 0.2 × x[k] + 0.8 × y[k-1]`。`real_speed` 保存滤波结果，同时供 PID 和上位机使用；滤波位于反馈通路中，会影响控制器的输入。系数越小，反馈越平滑，跟随转速变化也越慢。

PID 输出是电调电流指令计数；表中的 ±2000 是指令限幅。反馈 RPM 为转子转速，输出轴转速需要结合减速比换算。主循环包含阻塞串口发送、OLED 操作和 `Delay_ms(2)`；积分与微分按调用次数更新，实际周期还包括这些操作的耗时。

## 打开工程与上位机设置

使用 Keil MDK 打开本目录的 `project.uvprojx`，选择 `Target 1` 和 ARM Compiler 5，安装 STM32F1 设备支持包后执行 Rebuild。保留工程内现有的标准库、CMSIS、启动文件和相对路径；通过 SWD 下载时，在本机配置实际使用的调试器。

匿名上位机使用串口 115200、8N1，按下面的映射设置参数和自定义波形。参数 5 写入 1 后进入控制分支，写入 0 后发送零电流；其他值同样按停机处理。

| 参数 ID | 含义 | 上位机参数初值 / 换算 |
| --- | --- | --- |
| 1 | Kp | 300 → 3.00 |
| 2 | Ki | 2 → 0.02 |
| 3 | Kd | 10 → 0.10 |
| 4 | 目标转子转速 | 1000 → 1000 RPM |
| 5 | 运行标志 | 初值 0；1 为运行，其他值为停机 |

PID 初始化值和上位机参数初值是两组配置：进入运行分支并处理参数更新时，主循环才把参数 1～3 除以 100 后写入 PID。波形帧为 `0xF1`，有效数据 16 字节，按 8 个小端 `int16_t` 解码，顺序为电机 1 的反馈、目标，电机 2 的反馈、目标，依次到电机 4。

## 当前源码状态

沿用首次学习工程的目录与控制流程，整理时对运行标志和停机逻辑作了两处修正：

| 位置 | 修正内容 | 行为 |
| --- | --- | --- |
| `Hardware/AND_DT.c` 的 `Ano_GetData()` | 允许参数编号 1～5，拒绝 0 及大于 5 的编号 | 可正常读取第 5 项运行标志，越界编号返回 0 |
| `main.c`、`Hardware/Pid.c` | 非运行状态持续发送四路零电流，并调用 `PID_Reset()` 清理输出、积分和误差历史 | 保留增益、限幅和目标值；再次运行时重新累计 PID 状态；停机循环保留 2 ms 延时 |

2026-10-21 使用工程原配置 ARMCC 5.06 update 7 全量重建，0 错误、0 警告。主机模拟测试通过参数边界、运行标志读写、PID 状态清零及配置保留、停机/无效标志、运行→停止→再运行检查；未进行新的上板测试。零电流指令用于撤销驱动，电机仍可能因惯性转动，实机调试保留硬件断电方式。
